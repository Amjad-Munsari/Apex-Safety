Fill the third Plan 17-01 Wave-0 scaffold (`tests/scheduler/cron-reminder-decision.spec.ts`) with regression-grade assertions over the cron handler created in Plan 17-04. This is the safety net that prevents accidental drift on the four contract-critical behaviors of the cron:

1. Auth gate — 401 on missing/wrong Authorization header (when CRON_SECRET is configured).
2. PASS A filter chain — `.is('deleted_at', null)` + `.neq('status', 'completed')` + `.not('due_date', 'is', null)` (RESEARCH §Pitfall 5).
3. Cadence decision ladder — the monotonic 7d → 1d → overdue state machine that prevents double-sends.
4. Idempotency — `last_reminder_sent` is written AFTER `dispatchNotification` returns `ok:true`; on `ok:false` the column is left unchanged AND a `workflow_errors` row is inserted (RESEARCH §Pattern 4).

This is the only plan in Phase 17 that exercises the assembled cron route handler — Plan 17-02 specs the pure functions in isolation; Plan 17-05 specs the route's wiring of those functions plus its auth + filter + dedup contract.

The cron's cadence decision logic (from Plan 17-04 Task 1 `<action>` step 4):
```
if (row.due_date === iso(day7) && row.last_reminder_sent === null) cadence = "7d";
else if (row.due_date === iso(day1) && row.last_reminder_sent !== "1d" && row.last_reminder_sent !== "overdue") cadence = "1d";
else if (row.due_date < iso(today) && row.last_reminder_sent !== "overdue") cadence = "overdue";
else continue;
```

Mocking strategy (Vitest 3, jsdom):
- Mock `@supabase/supabase-js` so `createClient(URL, KEY)` returns a stub client. The stub provides:
  - `.from(table)` returning a chainable object whose terminal methods (`maybeSingle`, `single`, or direct await on a thenable chain) resolve to configurable values.
  - For PASS A: `.from("form_assignments").select().is().neq().not()` must terminate awaitably to a `{ data: rows, error: null }` shape.
  - For PASS A client contact lookup: `.from("client_users").select().eq().limit()` must terminate awaitably.
  - For PASS A update: `.from("form_assignments").update().eq()` must terminate awaitably.
  - For PASS A failure path: `.from("workflow_errors").insert()` must terminate awaitably.
  - For PASS B: `.from("form_assignments").select().eq().is().not().is()` must terminate awaitably.
  - For PASS B update: `.from("form_assignments").update().eq()` must terminate awaitably.
- Mock `@/lib/scheduler/send-reminder` so `sendAssignmentReminder` is a vi.fn returning configurable DispatchResult.
- Mock `@/lib/scheduler/generate-next-occurrence` so `generateNextOccurrence` is a vi.fn returning configurable GenerateResult.

The hoisting-safe vi.mock pattern (Plan 16-04 SUMMARY §Deviation 3, Plan 17-02 send-reminder.spec.ts):


Building the chainable Supabase stub (the load-bearing part — the cron's PASS A chain is `.select(...).is(...,null).neq(...,...).not(...,...,null)`):
- Approach: `supabaseFromSpy.mockReturnValue(chainable)` where `chainable` is a per-test-built object whose `.select()` / `.is()` / `.neq()` / `.not()` / `.eq()` / `.limit()` / `.update()` / `.insert()` methods all `return chainable`, and a separate `thenable` interface for awaiting the chain terminal.
- For terminal-via-await pattern (PostgREST builders are thenable): the chainable object includes a `.then(onFulfilled)` method that resolves to `{ data, error }`. This is how `await supabase.from(X).select().eq()` works in real code.
- For terminal-via-explicit-method (e.g. `.maybeSingle()`, `.single()`): the chainable's `.maybeSingle()` and `.single()` return promises directly.

In practice the spec needs only 3-4 distinct chainable instances:
1. PASS A SELECT (returns array of rows).
2. PASS A client_users SELECT (returns contact rows).
3. PASS A UPDATE (form_assignments dedup write).
4. PASS A workflow_errors INSERT (failure-path write).
5. PASS B SELECT (returns array of completed-recurring rows — can be empty for tests focused on PASS A).
6. PASS B UPDATE (recurrence_generated_at write).

A factory function inside the spec builds the chainable based on what `.from(tableName)` was called with.
