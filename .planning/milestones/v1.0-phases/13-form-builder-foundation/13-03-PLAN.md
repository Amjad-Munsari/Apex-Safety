<objective>
Build the coltorapps interpreter renderer that replaces the hand-rolled `components/forms/form-renderer.tsx`, and re-point the Phase 6 assessment fill flow onto it. This delivers the fill→validate→submit half of the cutover: a built form is fillable, submissions run full-stack validation, and every submission is pinned to its exact `template_version_id` so historical submissions render against their original schema.

Purpose: Completes the big-bang cutover (D-03) on the rendering side. The interpreter is the only consumer of `form_submissions`, and the assessment page is the single live `FormRenderer` call site (RESEARCH.md assumption A2 — confirmed: one import). Version pinning (RESEARCH.md Pitfall 2) is the critical correctness rule — the RSC must join via `template_version_id`, never to the template's latest version.

Output: `components/form-interpreter/` (interpreter-renderer + 7 per-entity renderers); rewired `app/admin/assessments/[id]/page.tsx` (RSC) and `assessment-client.tsx`; `submitAssessmentAction` in `app/admin/assessments/actions.ts`; filled `version-pin.test.ts`, `validate-values.test.ts`.
</objective>

<interfaces>
<!-- coltorapps-react interpreter contracts. Source: 13-RESEARCH.md Patterns 5-6. -->

useInterpreterStore(formBuilder, schema, { events? }) — client hook; returns interpreterStore.
interpreterStore.getEntityValue(entityId) / setEntityValue(entityId, value) — read/write a field value.
interpreterStore.getEntityError(entityId) — per-entity validation error.
interpreterStore.getEntitiesValues() — all values for submission.
interpreterStore.validateEntityValue(entityId) — re-validate one field.
<InterpreterEntities interpreterStore={...} components={{ [entityType]: Component }} entityId?={sectionId}> — renders fill inputs; `entityId` scopes to a section's children.
BuilderEntitiesEntityComponentProps<typeof formBuilder, "numberField"> — typed props for an entity renderer.

validateEntitiesValues(values, formBuilder, schema) — async; returns `{ success, data } | { success: false, entitiesErrors }`.

Live DB contract (migrations 001/005):
- form_submissions: id, template_version_id (FK to template_versions), answers_json (jsonb), status ('draft'|'submitted'|'reviewed'), submitted_at
- template_versions: id, schema_json (jsonb — coltorapps shape post-reseed)
- The assessment page currently uses adminClient (service role); the UUID gate regex stays.

Existing field components accept `surface?: "dark" | "cream"`: components/forms/{number,date,checkbox}-field.tsx are reusable as the render layer.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser interpreter store → submit server action | Client-collected form values are untrusted; they cross into a server action that writes `form_submissions` |
| Client-supplied submission identifier → schema selection | The version a submission validates against must come from server-held data, not a client parameter |
| Unauthenticated request → submit action | The submit endpoint must self-gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-09 | Tampering | `submitAssessmentAction` | mitigate | `validateEntitiesValues(rawValues, formBuilder, schema)` runs server-side before the DB write; values for entities not in the schema are rejected (RESEARCH.md Security Domain) — covered by `validate-values.test.ts` |
| T-13-10 | Tampering | Version selection for validation | mitigate | The schema is fetched from `template_versions` using the submission row's own `template_version_id` FK — the client cannot supply a different (e.g. weaker) version to validate against; proven by `version-pin.test.ts` |
| T-13-11 | Elevation of Privilege | `submitAssessmentAction` | mitigate | The action is guarded by `requireActorUserId` before any read/write |
| T-13-12 | Information Disclosure | Assessment RSC fetch | accept | The page uses the service-role `adminClient` and is reached only via the `proxy.ts` admin middleware gate; the UUID regex gate rejects malformed ids before any DB lookup. Phase 13 keeps this existing posture unchanged. |
| T-13-13 | Repudiation | Submission record | mitigate | `submitAssessmentAction` writes `submitted_at` and flips `status` to `'submitted'` atomically with `answers_json`, creating an auditable record pinned to its version |
</threat_model>
