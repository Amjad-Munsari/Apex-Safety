<objective>
Port the legacy n8n assessment-submission webhook from `submitAssessment` (lines 194-212) into the Phase 13+ `submitAssessmentAction` (lines 232-309) so that the modern validated-and-scrubbed admin submission path also fires the n8n Module 1 bridge — satisfying Phase 18 ROADMAP SC#5 ("A submission fires the n8n webhook for the AI report pipeline (Module 1 bridge)").

Why this is needed: per RESEARCH §Q5, the existing `submitAssessmentAction` already validates against the pinned schema (line 264-270), strips hidden answers (lines 277-280), writes the submission (lines 283-295), and fires the Vercel AI SDK draft generation inside an `after(...)` callback (lines 302-308). But it does NOT fire the n8n `N8N_ASSESSMENT_WEBHOOK_URL` webhook. The legacy `submitAssessment` (which lacks validation + scrub) IS firing the n8n webhook (lines 194-212). The two paths are out of sync. Phase 18 SC#5 wants the modern path to fire both — and the user-facing redirect must not wait on either.

Scope locks (cite each):
- The fire MUST be inside `after(...)` (Next.js post-response background task) so the user's redirect after submit isn't blocked on n8n's response or timeout. Either as a second `after(...)` registration OR as an extension of the existing AI-draft `after(...)` block (RESEARCH §Pattern 5 — both AI generation and webhook fire are post-response).
- The fire MUST be guarded by `if (process.env.N8N_ASSESSMENT_WEBHOOK_URL)` so dev / preview / test environments without the env var skip silently (matching the legacy `submitAssessment` guard at line 195).
- The fire MUST use `signal: AbortSignal.timeout(3000)` so a hung n8n endpoint doesn't keep the background task alive beyond 3 seconds (mirroring legacy line 201).
- On failure, insert a `workflow_errors` row with `workflow_name: 'assessment-submission-webhook'`, `error_message: String(err)`, `payload: { submissionId }` — and SWALLOW the error (do not re-throw). The submission has already been written; n8n being down is a downstream concern, not a reason to invalidate Matt's work.
- The legacy `submitAssessment` function (lines 166-215) is NOT modified. It remains as the older direct-submit path; its existing webhook fire stays untouched.
- The customer-side `submitAssignedFillByIdAction` (`app/client/assignments/actions.ts`) is NOT modified. Pitfall P7 (RESEARCH §Q9): customer submits do not trigger the AI pipeline OR n8n webhook — this is a permanent invariant, not a bug to fix.

This plan does NOT push migration 016 (Plan 18-03 does). It does NOT delete `lib/forms/fra-template.ts` (Plan 18-03 cleanup does). It does NOT update ROADMAP (Plan 18-03 does).

Purpose: ~15 lines of code + ~80 lines of test code. The action is small but load-bearing — without it, ROADMAP SC#5 is unsatisfied even after the seed is live.

Output: one file modified (`app/admin/assessments/actions.ts` — inline webhook fire inside an after() callback inside `submitAssessmentAction`), one new spec (`tests/scheduler/n8n-assessment-webhook.test.ts`).
