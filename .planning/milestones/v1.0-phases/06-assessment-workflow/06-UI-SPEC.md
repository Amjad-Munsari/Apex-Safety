## Surface Specs

### 1. Sidebar — "New Assessment" Button

**Location:** `components/app-sidebar.tsx` — below existing navigation items, above the bottom utility section.

**Anatomy:**
```
[ ▶ New Assessment ]   ← amber-500 bg, black text, full sidebar width button
```

- Style: `bg-amber-500 hover:bg-amber-400 text-black font-semibold text-sm rounded-sm px-4 py-2.5 w-full transition-colors`
- Icon: `Plus` (lucide), 16px, left-aligned
- Behaviour: Opens the Client + Template Selector dialog

**States:**
| State | Treatment |
|-------|-----------|
| Default | `bg-amber-500 text-black` |
| Hover | `bg-amber-400` with subtle `scale-[1.01]` |
| Active | `bg-amber-600` |
| Disabled | `opacity-50 cursor-not-allowed` |

### 3. Assessment Form Page `/admin/assessments/[id]`

**Layout:** Full-page, inherits admin layout (`px-8 py-8`). Form content centred to `max-w-3xl mx-auto`.

**Sticky Form Header (inside `<main>`):**
```
┌──────────────────────────────────────────────────────────────┐
│ ACME Fire Solutions           Progress ████████░░░ 78%       │ ← sticky top-0 bg-background/95 backdrop-blur border-b
│ Fire Risk Assessment (Type 3) [Save Draft] [Submit →]        │
└──────────────────────────────────────────────────────────────┘
```

- Container: `sticky top-0 z-10 bg-background/95 backdrop-blur border-b border-slate-800 py-3 px-0 -mx-8 px-8 mb-8`
- Client name: `text-sm font-medium text-slate-200`
- Template name: `text-xs text-slate-500 font-mono`
- Progress bar: `h-1.5 bg-slate-800 rounded-full` with `bg-amber-500` fill, animated via CSS width transition
- Progress label: `text-xs text-slate-400 font-mono tabular-nums` e.g. "78%"
- "Save Draft" button: `variant="ghost" text-slate-400 hover:text-white h-9 px-4 rounded-sm text-sm`
- "Submit Assessment" button: `bg-amber-500 hover:bg-amber-400 text-black font-semibold h-9 px-6 rounded-sm text-sm` — **disabled** until all required fields filled

**Form body:** Reuses existing `FormRenderer` component unchanged. No modifications to the renderer itself.

**"Anything Else" Appendix Section:**
Rendered as the final section of every assessment. Visually distinct from body sections.

```
┌──────────────────────────────────────────────────┐
│  ADDITIONAL OBSERVATIONS                         │ ← amber-500/60 left border (border-l-2)
│                                                  │
│  [ Tap mic or type any additional notes...     ] │ ← full Textarea + MicButton
│                                                  │
│  [📎 Add Photos]                                 │ ← MediaField component
└──────────────────────────────────────────────────┘
```

- Section wrapper: `border-l-2 border-amber-500/40 pl-6 py-2 mt-8`
- Section label: `text-xs font-mono uppercase tracking-widest text-amber-500/80 mb-4`
- Textarea: inherits FormRenderer styles — `bg-slate-950 border-slate-800 min-h-[120px] rounded-sm`
- Optional badge: `text-[10px] text-slate-500 uppercase tracking-wider` showing "Optional"

**Sticky Form Footer (bottom safe area):**
- `pb-24` on form container to prevent content hiding behind sticky submit button on mobile

### 4. Draft Recovery Dialog

**Trigger:** User navigates to "New Assessment" for a client who already has an active `draft` submission.

**Component:** shadcn `AlertDialog`

```
┌──────────────────────────────────────────┐
│  ⚠  Resume Existing Draft?              │ ← amber warning icon
│                                          │
│  An unsaved assessment for              │
│  ACME Fire Solutions exists              │
│  from 2 hours ago.                      │
│                                          │
│  [Start Fresh]    [Resume Draft →]       │
└──────────────────────────────────────────┘
```

- "Resume Draft" CTA: `bg-amber-500 text-black font-semibold` (primary)
- "Start Fresh": `variant="outline" border-slate-700 text-slate-300` (secondary — destructive intent but not red since it's the user's choice)
- Warning icon: `AlertTriangle` from lucide, `text-amber-400`, 20px
- Body text: `text-slate-300 text-sm leading-relaxed`

### 5. Post-Submission Toast

**Component:** shadcn `useToast` / Sonner (whichever is already wired in the project)

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Dialog focus trap | shadcn `Dialog` handles via Radix `FocusScope` |
| Keyboard navigation in client list | `role="listbox"` + `aria-selected` on client rows |
| Progress bar | `role="progressbar"` + `aria-valuenow={progress}` |
| Submit button disabled state | `disabled` attribute + `aria-disabled` |
| Draft recovery dialog | `AlertDialog` with `AlertDialogTitle` and `AlertDialogDescription` |
| MicButton | Existing `aria-label` from Phase 2 implementation |
