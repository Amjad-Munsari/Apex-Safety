# Phase 15 — UI Design Contract: Conditional Logic Engine

## New Interaction Contracts

This section specifies only what is NEW in Phase 15. All existing patterns (AttributeRow, toggle, option editor, select, input) are reused verbatim.

### 1. Conditional Logic Section in PropertiesPanel (Builder — admin only)

**Location:** Appended below all existing attribute editors inside `PropertiesPanel`, before the type footer `<div>`. Applies to every non-container entity (i.e., `hasCondLogic = !isSectionGroup` — containers cannot have visibility rules on themselves, but sections can be rule *targets*).

**Collapsed state (default, N = 0):**
```
┌──────────────────────────────────────────────┐
│ [GitFork icon 14px]  CONDITIONAL LOGIC  [›]  │  ← font-mono text-[10px] uppercase tracking-widest
└──────────────────────────────────────────────┘
```
- The `›` chevron is `ChevronRight` (Lucide, 12px), rotates 90° to `ChevronDown` when expanded.
- No badge when N = 0.
- `GitFork` Lucide icon (14px) at left — signals "branching logic". Fallback: `Workflow` icon.

**Collapsed state (default, N > 0):**
```
┌──────────────────────────────────────────────┐
│ [GitFork]  CONDITIONAL LOGIC (2)  [›]        │
└──────────────────────────────────────────────┘
```
- Badge `(N)` is inline in the label text, same mono style — not a pill. Renders as `CONDITIONAL LOGIC (2)`.

**Expanded state:**
```
┌──────────────────────────────────────────────────────────┐
│ [GitFork]  CONDITIONAL LOGIC (2)  [˅]                    │
├──────────────────────────────────────────────────────────┤
│  Combine rules with: [ AND ][ OR ]  ← segmented toggle   │
│                                                           │
│  Row 1: [Field dropdown▼] [Operator▼] [Value] → [Action▼] [🗑] │
│  Row 2: [Field dropdown▼] [Operator▼] [Value] → [Action▼] [🗑] │
│                                                           │
│  [+ Add condition]                                        │
└──────────────────────────────────────────────────────────┘
```

**AND/OR segmented toggle:**
- Width: full-width two-chip control, `w-full grid grid-cols-2`.
- Height: `h-7` (28px).
- Chip text: `AND` / `OR`, `text-xs font-mono uppercase`.
- Active chip: `bg-[#3b8273] text-white` (dark) / `bg-[#1a1a1a] text-white` (cream).
- Inactive chip: `bg-white/10 text-white/40` (dark) / `bg-[#e5e1d8] text-[#8a857f]` (cream).
- Border radius: `rounded-[3px]` (matches existing inputs).

**Rule row layout:**
- Horizontal flex, `gap-1.5`, `items-center`.
- **Source field dropdown** (`[Field ▼]`): `flex-1 min-w-0` — shows field label truncated. Placeholder: `— field —`.
- **Operator dropdown** (`[Operator ▼]`): `w-28` fixed — shows operator label (`equals`, `not equals`, `contains`, `> `, `< `, `empty`, `not empty`). Options filtered by source field type per D-06.
- **Value input** (`[Value]`): `flex-1 min-w-0` — text input for most operators; hidden/zero-width for `isEmpty` / `isNotEmpty` operators (no value needed). Placeholder: `value…`.
- **Arrow separator** (`→`): `text-white/20` (dark) / `text-[#8a857f]` (cream), `text-xs`, `px-0.5`, non-interactive.
- **Action dropdown** (`[Action ▼]`): `w-24` fixed — options: `show`, `hide`, `require`.
- **Delete button** (`🗑`): `Trash2` Lucide icon, 14px, `text-white/20 hover:text-[#8b2b21]` (dark) / `text-[#8a857f] hover:text-[#8b2b21]` (cream). Touch target: `w-6 h-6 flex items-center justify-center`.
- Full row height: `min-h-[32px]` with `py-1`.

**Value input visibility rule:** when operator is `isEmpty` or `isNotEmpty`, the value input renders as `hidden` (not removed from DOM) with `w-0 overflow-hidden p-0 border-0` so the row layout does not jump.

**"Add condition" button:**
- Full width, `w-full`.
- Style: dashed border, `border-dashed border-white/10` (dark) / `border-dashed border-[#e5e1d8]` (cream).
- Text: `+ Add condition`, `text-xs font-mono`, `text-white/30 hover:text-[#3b8273]` (dark) / `text-[#8a857f] hover:text-[#1a1a1a]` (cream).
- Height: `h-7`.

**Scope restriction note:** When the selected entity is inside a `repeatingSection` and the user opens the source-field dropdown, fields from other repeatingSection instances are not listed (D-03). If no eligible sources exist (e.g., a root-level field has no siblings), the dropdown shows a single disabled option: `— no eligible fields —`.

### 2. Save-Time Cycle Error (Builder)

**Location:** Displayed as a toast + an inline banner inside PropertiesPanel (or the publish/save button area — exact host is the save/publish action call site).

**Toast (Sonner):**
- Type: `toast.error(...)` — red destructive.
- Title: `Circular rule detected`
- Body: `"[Field A] → [Field B] → [Field A]"` — entity labels joined with `→`. If cycle is longer than 3 hops, truncate at 3 and append `…`.
- No action button (admin must manually remove a rule to break the cycle).

**Inline PropertiesPanel error state:** When the currently selected entity is part of a detected cycle, a warning row appears above the "Add condition" button:
```
┌─────────────────────────────────────────────────────────────┐
│ [AlertTriangle 12px]  Circular rule: [Label A] → [Label B]  │
│  Remove a rule above to break the cycle.                     │
└─────────────────────────────────────────────────────────────┘
```
- Container: `rounded-[3px] border border-[#8b2b21]/40 bg-[#8b2b21]/10 px-3 py-2`.
- Text: `text-[10px]` with `text-destructive` (inherits CSS variable).
- Icon: `AlertTriangle` Lucide, 12px.

---

### 3. Hidden Field Behaviour (Interpreter — fill time)

**When a field is hidden (`visible === false`):**
- The field's DOM is fully unmounted from the interpreter renderer output (not `visibility: hidden` or `opacity-0`). This is a zero-layout approach — the form reflows as if the field never existed.
- No transition animation on hide/show — abrupt removal to avoid confusing motion on a professional assessment form.
- Adjacent fields close the gap naturally via the existing `flex flex-col gap-4` (or `gap-6`) layout on the interpreter form.

**When a sectionGroup or repeatingSection is hidden:**
- The entire container and all its children are unmounted — recursive collapse per D-01.
- No "X fields hidden" disclosure. Hidden is silent.

**Required-if field that becomes hidden:**
- Hidden trumps required-if per D-07. The field does not show a required asterisk and does not block submission.

---

### 4. Required-If State Indicators (Interpreter — fill time)

When a `require` rule fires and makes a previously optional field required:
- The field's label gets a required asterisk `*` appended — `after:content-['*'] after:text-destructive after:ml-0.5` — matching the static-required fields' pattern from Phase 13.
- No other visual change. The field itself does not change colour or border.
- If the field is unfilled at submit attempt, it shows the same validation error style as any required field: `border-destructive` + error text beneath (Phase 13/14 pattern — reuse without change).

---

### 5. Progress Bar Adjustment (Interpreter — fill time)

The `computeFormProgress` utility will be updated to exclude hidden fields from the required-field denominator. This produces no new UI; the existing `onProgressChange` callback in `InterpreterRenderer` already drives the header progress bar. No visual change to specify — the bar just reflects a corrected count.

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Section header (0 rules) | `CONDITIONAL LOGIC` | Mono caps, matches existing label pattern |
| Section header (N > 0) | `CONDITIONAL LOGIC (N)` | N = count of rules |
| AND/OR toggle — AND chip | `AND` | Mono caps |
| AND/OR toggle — OR chip | `OR` | Mono caps |
| Source field dropdown placeholder | `— field —` | Em-dash + space, matches `— select field —` in computedField |
| Operator dropdown placeholder | `— operator —` | Same pattern |
| Value input placeholder | `value…` | Lowercase, ellipsis |
| Action dropdown placeholder | `— action —` | Same pattern |
| Action option: show | `show` | Lowercase |
| Action option: hide | `hide` | Lowercase |
| Action option: require | `require` | Lowercase |
| No-eligible-fields option | `— no eligible fields —` | Shown when scope restricts all candidates |
| Add condition button | `+ Add condition` | Sentence case, `+` prefix |
| Empty state (no rules, collapsed) | *(no text — badge absent)* | Collapsed section is self-explanatory |
| Cycle error toast title | `Circular rule detected` | Title case |
| Cycle error toast body | `[Label A] → [Label B] → …` | Entity labels, `→` separator |
| Cycle error inline first line | `Circular rule: [Label A] → [Label B]` | |
| Cycle error inline second line | `Remove a rule above to break the cycle.` | Imperative, action-oriented |
| Save blocked (publish button) | `Fix circular rules before publishing` | Shown as disabled-state tooltip on publish button |

**Destructive action:** Delete rule (trash icon button). No confirmation dialog — single click removes the rule row immediately (undo is out of scope; the admin can re-add). The trash icon itself is the only affordance; no modal.
