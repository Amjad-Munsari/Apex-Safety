useBuilderStore(formBuilder, { initialData?: { schema }, events? }) — client hook; returns builderStore.
builderStore.addEntity({ type, attributes }, { parentId? }) — add entity; parentId nests in a sectionGroup.
builderStore.setEntityAttribute(entityId, attributeName, value) — write one attribute.
builderStore.setEntityIndex(entityId, index, { parentId? }) — reorder / reparent.
builderStore.deleteEntity(entityId) — remove entity.
builderStore.getSchema() — returns canonical { entities, root } shape.
useBuilderStoreData(builderStore, selector) — selective re-render.
<BuilderEntities builderStore={...} components={{ [entityType]: Component }}> — renders entity cards.

validateSchema(rawSchema, formBuilder) — async server validator (Plan 01).

Live DB contract (migrations 003-005):
- form_templates: id, name, template_type, owner_id (polymorphic, no FK), owner_type ('admin'|'customer'), is_published, parent_template_id
- template_versions: id, template_id, version_number, schema_json (jsonb), published_at, created_by (no FK), deleted_at
- requireActorUserId("admin") from @/lib/auth-helpers — returns the actor UUID, throws if unauthenticated
- getClientContext() from @/lib/auth-helpers — returns { client_id, ... } or null

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser builder store → server action | The client-held schema (`getSchema()` output) is untrusted; it crosses into a server action that writes to the DB |
| Unauthenticated request → template server action | Anyone can POST to a server action endpoint; the action must self-gate |
| Customer user → another org's template | RLS + ownership checks must scope customer writes to their own org |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Tampering | `saveDraftAction` / `publishTemplateAction` | mitigate | Call `validateSchema(rawSchema, formBuilder)` server-side before any INSERT; reject (throw, no DB write) when `result.success` is false — a crafted `schema_json` with arbitrary entity types cannot be persisted (RESEARCH.md Security Domain) |
| T-13-05 | Elevation of Privilege | All template server actions | mitigate | First line of every action is `requireActorUserId("admin")` (admin actions) or `getClientContext()` (client actions); an unauthenticated caller is rejected before any read/write — covered by the save-draft test |
| T-13-06 | Tampering | `form_templates` insert (owner_id) | mitigate | Admin inserts force `owner_type='admin'`; customer inserts force `owner_type='customer'`, `owner_id=ctx.client_id` (org UUID). The `owner_type` CHECK from migration 003 plus the `'client'`-absent grep assertion prevents a misdiscriminated row that would slip past RLS |
| T-13-07 | Information Disclosure | Customer template reads | accept | Cross-org isolation is enforced by the RLS policies already shipped in migrations 003/004 (`owner_id IN (SELECT client_id FROM client_users WHERE id = auth.uid())`); Phase 13 adds no new read path. Full two-account RLS verification is Phase 16 scope. |
| T-13-08 | Tampering | Published `template_versions` row | mitigate | Removal of the in-place `.update({ schema_json })` path guarantees a published version is never mutated; the save-draft test asserts the prior row is unchanged after a re-save |
</threat_model>
