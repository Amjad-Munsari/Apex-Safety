# Phase 13 — UI Design Contract: Form Builder Foundation

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | shadcn | `components.json` detected |
| Style | base-mira | `components.json` → `"style": "base-mira"` |
| Base color | mist | `components.json` → `"baseColor": "mist"` |

The builder UI lives under `/admin/templates` — it uses the **admin surface** (dark). The interpreter/renderer on the client side uses the **client surface** (cream). Both must be supported because AGENTS.md requires the builder component to be reusable across surfaces.

## Spacing Scale

Declared values (multiples of 4 only). Standard 8-point scale applies.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline dividers |
| sm | 8px | Between palette items, between canvas field rows (gap-2) |
| md | 16px | Panel internal padding, toolbar horizontal padding (px-4) |
| lg | 24px | Canvas horizontal padding (px-6), section grouping |
| xl | 32px | Page-level top/bottom padding, major section breaks |
| 2xl | 48px | Empty-state vertical centering gap |
| 3xl | 64px | Not used in builder panels (builder is edge-to-edge fixed) |

**Exceptions:**
- Builder wrapper: `fixed inset-0` — full viewport, no page margins.
- Toolbar height: 56px (h-14). Pinned top, shrinks nothing.
- Bottom status bar height: 32px (h-8). Pinned to canvas column bottom.
- Palette column width: 224px (w-56). Fixed, not resizable.
- Properties panel width: 288px (w-72). Fixed, not resizable.
- Canvas field card max-width: 672px (max-w-2xl), centred in canvas column.
- Drag overlay: no additional padding — matches field card dimensions.
- Touch targets for palette field-type buttons: minimum 44px height (WCAG 2.5.5). Source: FORM-02/FORM-03 requirements.

## Typography

The project uses three fonts. All sizes below apply to the admin (dark) builder surface unless noted.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Body | 14px (text-sm) | 400 regular | 1.5 | Inter (sans) | Properties panel labels, field help text, palette descriptions |
| Label / mono | 10px–12px (text-xs) | 400 regular | 1.4 | JetBrains Mono | Toolbar status tags (SAVED, DRAFT, LIVE), field-type labels, bottom bar field count, keyboard shortcuts |
| Form title | 18px (text-lg) | 400 regular | 1.3 | Newsreader (serif) | Template name inline input in the toolbar |
| Page heading | 32px (text-[32px]) | 400 regular | 1.2 | Newsreader (serif) | Templates list page h2 (existing pattern from `page.tsx`) |

Two font weights maximum in the builder: 400 (regular) and 600 (semibold). Semibold is reserved for field labels inside the canvas card and section group titles. All mono strings are uppercase + tracking-wider.

**Renderer (client surface) typography:** inherits the same scale but renders against cream background (`data-surface="client"`). Field labels use Inter 14px/400. Section titles use Newsreader 18px/400.

## Interaction Contract

### Three-Panel Builder Layout (admin)

```
┌────────────────────────────────────────────────────────┐
│  ← Back  |  [Template Name ——————————]  TYPE  badge  Save  Publish  │ h-14 toolbar
├──────────┬─────────────────────────────┬───────────────┤
│  Palette │        Canvas               │  Properties   │
│  w-56    │    flex-1, overflow-y-auto  │  w-72         │
│  left    │    px-6 py-4                │  right        │
│  panel   │    max-w-2xl mx-auto        │  panel        │
│          │    gap-2 between cards      │               │
│          ├─────────────────────────────┤               │
│          │  [status bar h-8]           │               │
└──────────┴─────────────────────────────┴───────────────┘
```

**Palette panel:** Scrollable list of 7 field-type buttons. Each button: icon + label, min 44px height, full-width, `variant="ghost"` styling on dark surface. Clicking adds field to bottom of canvas; dragging allows drop at any position.

**Canvas column:** Vertical sortable list of field cards (max-w-2xl, centred). Each card:
- Drag handle on left (GripVertical icon, 16px, muted)
- Field type icon (16px)
- Field label text (14px/600 semibold)
- Field type badge (10px mono uppercase, muted)
- Duplicate + Delete actions on right (appear on hover; 32px icon buttons)
- Selected state: border changes from `white/10` to `teal/50` with a left accent bar

**Properties panel:** Scrollable form. Renders attribute fields for the selected entity only. Unselected state shows centred hint text "Select a field to configure" in 12px mono.

**sectionGroup entity visual treatment:**
- Canvas renders as a rounded container card that visually groups child field cards
- Section title uses Newsreader 16px/400
- Drop zone inside section is visually distinct (inset dashed border, 2px, `white/10`) when dragging a field over it

### Drag and Drop

- Activation constraint: `distance: 5` (prevents accidental drag on click)
- Drag overlay: ghost card with field label, `opacity-90`, `shadow-2xl`, teal accent border — follows cursor
- Valid drop zones: between any two fields on canvas, inside a sectionGroup container
- Invalid drop: no visual change to palette item positions; drag snaps back
- Keyboard drag: enabled via `KeyboardSensor` with `sortableKeyboardCoordinates`

### Save Flow

1. User clicks "Save draft": button shows spinner, label changes to "Saving…"
2. On success: label resets; "Saved" tag appears in teal mono text for 2 seconds, then disappears
3. On failure: "Save failed" tag appears in destructive red
4. While `isPending`: both Save and Publish buttons are disabled
5. Unsaved indicator: "UNSAVED CHANGES" badge in amber mono, pulse animation, visible in bottom status bar

### Publish Flow

1. User clicks "Publish": browser `confirm()` dialog (existing pattern, no modal component) — text: "Publish v{N}? This version will become immutable and be available to assign to clients."
2. On confirm: same pending/saved/error states as save flow
3. After publish: toolbar shows "LIVE v{N}" teal badge; publish button remains available (to publish future drafts)

### Preview Mode

- A toggle in the toolbar ("Preview" / "Edit") switches the canvas from builder mode to interpreter mode
- In preview mode: canvas renders the coltorapps interpreter, no field card selection, no drag handles
- Properties panel hides in preview mode (or shows a "Preview active — editing disabled" hint)
- No data is saved during preview; switching back to Edit mode restores builder state

### Template List Page (`/admin/templates`)

- Grid: 1 column on mobile, 2 columns on md, 3 columns on xl
- Template card: dark card (`bg-[#1c1c1c]`), rounded-sm, shows name (serif 18px), type (mono 10px), version badge, published/draft status badge
- Empty state: centred card, icon, "No templates yet" / "Create your first form template to get started" (see Copywriting)

### Renderer (Interpreter) — `/admin/templates/[id]/preview` and client fill surface

- Single-column form, max-w-2xl, centred, `py-8 px-4` on mobile, `py-12 px-0` on desktop
- Each field renders with: label (14px/600), optional help text (12px muted), input component, error message (12px destructive, below input)
- sectionGroup: renders as a labelled section with Newsreader 16px heading and divider below
- Submit button: full-width on mobile, auto-width right-aligned on desktop, `variant="default"` (black fill on client surface)
- Validation errors surface inline below each field; a summary does not appear at top

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA — builder | "Publish" | Action in toolbar; publishes current version |
| Secondary CTA — builder | "Save draft" | Saves without publishing |
| Toolbar back link | "Back to Templates" | Uppercase mono, arrow left icon |
| Primary CTA — renderer | "Submit form" | Submit button at bottom of interpreter |
| Empty canvas heading | "Drag fields from the left panel" | 14px mono, centred in canvas |
| Empty canvas subtext | "or click a field type to add it" | 12px muted, centred below heading |
| Empty template list | "No templates yet" | 14px mono, in empty-state card |
| Empty template list subtext | "Create your first form template to get started" | 12px muted below heading |
| Properties panel — no selection | "Select a field to configure" | 12px mono, centred in panel |
| Save status — saving | "Saving…" | Button label while pending |
| Save status — saved | "Saved" | Teal mono tag; auto-dismisses after 2 s |
| Save status — error | "Save failed" | Destructive mono tag; persists until next action |
| Unsaved indicator | "Unsaved changes" | Amber mono, pulse, bottom status bar |
| Publish confirm dialog | "Publish v{N}? This version will become immutable and be available to assign to clients." | Browser `confirm()` — no custom modal |
| Draft badge | "DRAFT v{N}" | Amber badge in toolbar when draft exists |
| Live badge | "LIVE v{N}" | Teal badge in toolbar when published |
| Unpublished edits badge | "UNPUBLISHED EDITS" | Amber badge alongside LIVE badge |
| Field count — bottom bar | "{N} field" / "{N} fields" | Pluralised correctly |
| Preview mode toggle | "Preview" / "Edit" | Toggle in toolbar |

**Destructive actions:**
- Delete field: No confirmation dialog — delete is instant on the canvas (undo not required in Phase 13). Field is removed from builder store immediately. Rationale: fields are unsaved state; the last saved version is always recoverable via re-load.
- Drop + reseed (DB): No UI for this — it is a migration-time operation performed by the executor, not an in-app action.

**Error states (renderer):**
- Validation error per field: "{Field label} is required." / "{Field label} must be a valid number." — displayed inline below the input in 12px destructive colour.
- Submission API failure: Sonner toast (top-right, `richColors`) — "Submission failed. Check your connection and try again."

## Accessibility Contract

- All palette drag items must have `aria-label` describing the field type being added.
- Drag handles must have `aria-describedby` pointing to instructions: "Press space to pick up, arrow keys to move, space to drop."
- Properties panel inputs must be associated with labels via `htmlFor` / `id` pairing.
- Focus must return to the canvas field card after a field is deleted from the properties panel.
- Publish confirm dialog (browser native) is inherently accessible — no custom replacement needed in Phase 13.
- Minimum 44px touch targets: palette field-type buttons, field card delete/duplicate icon buttons.
