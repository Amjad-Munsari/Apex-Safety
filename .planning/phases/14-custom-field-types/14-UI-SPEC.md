# Phase 14 — UI Design Contract: Custom Field Types

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value | Source |
|----------|-------|--------|

Phase 14 adds 6 specialty renderers and builder surface extensions. No new design system decisions — all tokens are inherited from Phase 13. The builder lives under `data-surface="admin"` (dark); the fill surface lives under `data-surface="client"` (cream). All new renderers accept `surface?: "dark" | "cream"` and must render correctly on both surfaces.

## Interaction Contract

### Palette Extension — Two-Section Layout

The `FieldPalette` component grows from 7 buttons to 13 buttons. The single "Field Types" header is replaced by two labelled sections: "Basic Types" (7 existing buttons) and "Specialty" (6 new buttons). The section header style matches the existing `px-4 py-3 border-b` pattern with `font-mono text-[10px] uppercase tracking-widest` header text.

**Specialty section (in order on palette):**
1. Signature — PenLine icon — "Draw and capture a handwritten signature"
2. Rating — Star icon — "Star-based numeric rating 1–N"
3. Photos — Camera icon — "Multi-photo capture with compression"
4. Location — MapPin icon — "GPS coordinates with map preview"
5. Computed — Calculator icon — "Auto-computed PAS 79 risk score"
6. Repeating Section — ListOrdered icon — "Repeat a group of fields N times"

All specialty buttons: same `min-h-[48px]` touch target, same icon box + label + description layout as existing palette buttons. `EntityType` union in `field-palette.tsx` expands to include all 6 new types.

**Builder canvas — specialty field cards:** Specialty entities appear as canvas cards with the same drag-handle / icon / label / type-badge / duplicate+delete layout as basic fields. The only visual difference is the field type badge (12px mono uppercase) which shows the specialty type name (e.g., "SIGNATURE", "RATING", "COMPUTED").

**repeatingSection on canvas:** Renders as a rounded container card (same treatment as `sectionGroup`) that groups child field cards. Visual treatment:
- Section title uses Newsreader 18px/400 (same as sectionGroup heading)
- Container border: `border-2 border-dashed border-[#3b8273]/40` when empty, solid `border-white/10` when it has children
- Drop zone inside: inset dashed border `border-dashed border-white/10` when dragging over
- Children are rendered in a nested sortable list within the container card
- "Add fields here" placeholder text in 12px mono muted when empty (not an "Add Instance" button — that is a fill-time action)

### Properties Panel Extensions

New attribute editors appear in `PropertiesPanel` for specialty entity types. All editors follow the existing `AttributeRow` pattern (10px mono label + input + hint).

**Attributes common to all non-section specialty entities (attachPhotos):**
- Toggle (same w-10 h-5 rounded-full pattern): "Attach Photos" label, hint: "Allow photos to be attached to this field when filling". `attrs.attachPhotos` boolean, default OFF.

**ratingField-specific:**
- Number input "Max Rating" (min 2, max 10, default 5): `attrs.maxRating`. Hint: "Number of stars shown (2–10)".

**signatureField-specific:**
- No additional configurable attributes beyond standard Label / Required / Help Text / attachPhotos. Signature canvas dimensions are hardcoded (180px height); no builder control needed.

**multiPhotoField-specific:**
- Number input "Max Photos" (min 1, max 20, default 5): `attrs.maxPhotos`. Hint: "Maximum number of photos allowed".

**geolocationField-specific:**
- No additional configurable attributes beyond standard Label / Required / Help Text / attachPhotos. Map library and capture behaviour are hardcoded.

**computedField-specific:**
- Formula display (static, read-only): "Formula: PAS 79" — rendered as a non-editable label+value row. Teal mono text to distinguish from editable attributes.
- Entity ID dropdown "Likelihood Source": `<select>` listing all non-section, non-computed entities in the current form by label. Empty option "— select field —". `attrs.inputs.likelihood` = selected entity UUID.
- Entity ID dropdown "Consequence Source": same pattern. `attrs.inputs.consequence` = selected entity UUID.
- Hint under each dropdown: "Select the field that provides this value (must be a number 1–5)."

**repeatingSection-specific:**
- Section Title text input: `attrs.title` (same as sectionGroup pattern)
- Description textarea: `attrs.description` (same as sectionGroup pattern)
- Number input "Min Instances" (min 0, max 50, default 0): `attrs.minInstances`. Hint: "Minimum filled instances required to submit (0 = optional)".
- Number input "Max Instances" (min 1, max 50, default blank = unlimited): `attrs.maxInstances`. Hint: "Leave blank for no upper limit".
- No attachPhotos toggle on repeatingSection (it is a container, not a field — per D-05 "every non-section entity").

### Specialty Renderer Specifications

All new renderers follow the exact `EntityComponentProps` + `surface` prop pattern from `select-field-renderer.tsx`. All surface tokens follow the dark/cream `surfaceTokens` object pattern. All renderers are "use client" components.

#### signatureFieldRenderer

Wraps the existing `SignatureField` component from `components/forms/signature-field.tsx`. The renderer wrapper adds:
- Field label (14px/600 semibold, same as other renderers)
- Required asterisk if `attrs.required`
- Help text below label (12px muted)
- Error message below canvas (12px destructive)
- Upload lifecycle: on "Done" click, renderer calls `uploadMediaAction(submissionId, entityId, dataUrl, "image", clientId)` (server action). While uploading: canvas area shows a loading overlay with `Loader2` spinner + "Saving signature…" label. On success: `setValue(storagePath)`. On failure: toast error "Failed to save signature. Try again."
- Value display: once a storage path is set, show the preview state of `SignatureField` (reads from a signed URL via `adminClient.storage.from("form-media").createSignedUrl`). Alternatively, keep the base64 preview in component state until reload and only store path in coltorapps.

**Signature canvas interaction states:**
- Idle (no strokes): border `border-[#e5e1d8]` cream / `border-slate-800` dark. Instructions: "Sign with mouse or finger."
- Drawing active: amber border accent (`border-amber-500/60` cream / `border-amber-500/50` dark).
- Has strokes: "Tap Done to capture." instruction.
- Signed (preview mode): shows captured signature image, "Signed" mono label, Redraw + Remove ghost buttons.
- Uploading: spinner overlay on canvas area, buttons disabled.
- Error: destructive error message below canvas, canvas re-enabled.

#### ratingFieldRenderer

Wraps `RatingField` from `components/forms/rating-field.tsx`. The renderer wrapper adds:
- Field label (14px/600 semibold)
- Required asterisk if `attrs.required`
- Help text (12px muted)
- Star row: 5–10 stars depending on `attrs.maxRating` (default 5). Star size: 28px (`h-7 w-7`) with `p-1` padding = 36px per star. **Accessibility requirement:** wrap each star button in a `min-w-[44px] min-h-[44px]` container or add `p-2` (8px padding, giving 28px + 16px = 44px total touch target) to achieve WCAG 2.5.5 compliance. The `min-w-[44px] min-h-[44px]` wrapper approach is preferred.
- Score display: "{current} / {max}" in 14px JetBrains Mono tabular-nums, right of star row.
- Clicking same-rated star deselects (returns to 0).
- Error message (12px destructive).

#### multiPhotoFieldRenderer

Wraps `MultiPhotoField` from `components/forms/multi-photo-field.tsx`. The renderer wrapper adds:
- Field label (14px/600 semibold)
- Required asterisk if `attrs.required`
- Help text (12px muted)
- Photo grid: 2 columns on mobile (`grid-cols-2`), 3 columns on sm (`sm:grid-cols-3`), `gap-3` (12px — acceptable between grid breakpoint and standard sm=8px token; matches existing implementation).
- Each photo cell: `aspect-square rounded-sm overflow-hidden border`. Photo thumbnail fills cell via `object-cover`.
- Remove button: `h-6 w-6` destructive icon button, appears on hover (desktop) / always visible (mobile — no hover state). `aria-label="Remove photo {N}"`.
- Add cell (dashed border): "Add Photo" label + Plus icon. Visible only when `photos.length < maxPhotos`. Camera icon opens native file picker (`capture="environment"` for mobile). `accept="image/*"`.
- Processing state: `Loader2` spinner in add cell while `isProcessing`.
- Count label: "{N} / {maxPhotos}" in 12px mono uppercase tracking-wider, below grid.
- Upload lifecycle: same fire-and-forget pattern as signature. Each photo compresses via `use-media-processor`, then calls `uploadMediaAction`. Storage path replaces the blob URL in state.

#### geolocationFieldRenderer

Wraps `GeolocationField` from `components/forms/geolocation-field.tsx` and adds the Leaflet map and desktop accuracy badge (D-12).

**Renderer layout (below the field label):**
1. Capture panel (`rounded-sm border p-4 flex items-start gap-3`) — existing GeolocationField treatment.
2. Map preview — shown below the capture panel once coordinates are captured. Dynamically imported with `ssr: false`. Height: 200px, full-width, `rounded-sm overflow-hidden`.
3. Desktop accuracy badge — shown above or overlaid on the map when `position.coords.accuracy > 100m` OR when user agent does not match mobile pattern. Badge: `inline-flex items-center gap-2 px-2 py-1 rounded-sm text-xs font-mono bg-amber-100 text-amber-900 border border-amber-300`. Text: "Desktop capture — verify pin on map". AlertTriangle icon (12px) prepended.
4. "Click map to adjust pin" instruction — shown in 12px muted text below map when `onClickPin` is available (i.e., field is editable). Text: "Click the map to move the pin to the correct location."

**Capture panel states:**
- Loading: `Loader2` spin icon + "Acquiring GPS coordinates…" muted text.
- Success: MapPin icon + "Lat: {value.lat.toFixed(4)}, Lng: {value.lng.toFixed(4)}" mono display + "±{accuracy}m · {time}" secondary line.
- Permission denied: `AlertCircle` destructive icon + "Location permission was denied. Enable it in your browser to capture coordinates."
- Unavailable: `AlertCircle` destructive icon + "Location is currently unavailable."
- Error: `AlertCircle` destructive icon + "Couldn't get your location. Try again."
- Refresh button: ghost, "Refresh" label + RefreshCw icon, right of panel. Disabled while loading.

**Map interaction:**
- `MapContainer` renders at `zoom={15}`, centred on captured coordinates.
- Single `Marker` at captured position (Leaflet default icon — executor must fix the Webpack marker-icon path per RESEARCH.md Pitfall 1).
- Clicking on the map fires `onClickPin(lat, lng)` which updates the value in the store. The marker moves to the clicked position.
- Attribution: `© OpenStreetMap contributors` — required by OSM tile policy; do not remove.
- Map is only interactive (click-to-pin enabled) when the field is in fill mode (not read-only).

#### computedFieldRenderer

Read-only. No user input. Subscribes to dependency entity values via `useInterpreterEntitiesValues`.

**Renderer layout:**
1. Field label (14px/600 semibold) + help text (12px muted, if set).
2. Risk level badge — full-width pill: `px-4 py-3 rounded-sm text-sm font-semibold border` + PAS 79 colour class. Content: "{level} — Score: {score}" (e.g., "Moderate — Score: 6").
3. Pending state (either dependency is unset): `px-4 py-3 rounded-sm text-sm border border-dashed` in `border-white/10` (dark) / `border-[#e5e1d8]` (cream) + muted text: "Fill in likelihood and consequence fields above to compute risk."
4. Configuration error state (dependency entity IDs not set in builder): same pending style + text: "Computed field not configured — set inputs in the builder."

**Reactivity:** No animation on update. The badge value updates immediately on dependency change via `useInterpreterEntitiesValues`. No transition or fade. "No subtle fade" per the research note that a sudden colour change is the signal.

**Read-only indicator on builder canvas (preview):** Canvas card shows "COMPUTED" type badge + "PAS 79" formula badge as a second inline badge in the card header row (12px mono, muted).

#### repeatingSectionRenderer

Most complex renderer. Manages `instances[]` in local React state, synced to `interpreterStore` via `setValue`.

**Renderer layout:**
1. Section heading row: Newsreader 18px/400 title (from `attrs.title`), muted description below (14px/400), instance count badge "{N} instance" / "{N} instances" in 12px teal mono (right-aligned in heading row).
2. Instance cards: Each instance is a card (`rounded-sm border bg-card`). Cards stack vertically with `gap-3` (12px).
3. Each instance card layout:
   - Card header: small numbered indicator "# {N}" in 12px mono muted (left) + Collapse/Expand icon button (ChevronDown/ChevronUp, 16px, ghost) + Remove button (X, 16px, ghost destructive on hover) (right). Header height: 36px (h-9).
   - Card body (collapsible): renders the template children as a mini-form with `gap-4` between child fields. Uses the same renderer map but rendered inline within the instance.
   - Card body is expanded by default. Collapsed state shows only the header row.
4. Add instance button: full-width, dashed border, `h-10` (40px), "Add {title || "instance"}" label + Plus icon. Shown below all instance cards. Disabled and muted when `instances.length >= attrs.maxInstances` (if maxInstances set).
5. Min-instances validation message: shown below Add button when submit is attempted with `instances.length < attrs.minInstances`. Format: "{title || "This section"} requires at least {minInstances} {instance|instances}." in 12px destructive.

**Instance state:**
- New instance added: card is expanded, receives empty values, appears at bottom with a subtle `animate-in-fade` (0.3s, existing keyframe in globals.css).
- Removed: card disappears immediately. Instance indices re-number (not using UUIDs for display labels, just ordinal position).
- Collapsed: card body is hidden via `hidden` class (no transition needed in Phase 14 — conditional logic that reveals this with animation is Phase 15).

**Max instances enforcement:**
- When `instances.length >= attrs.maxInstances`: Add button shows as disabled + `opacity-50`. Tooltip or inline text: "Maximum {maxInstances} instances reached."
- No visual "full" state on the container card — the disabled Add button is sufficient.

**Empty state (zero instances):**
- No instance cards visible.
- Add button is the only CTA.
- No empty-state illustration — the Add button is self-explanatory with the section title.

### STT Mic Button — Text and Textarea Renderers

Both `textFieldRenderer` and `textareaFieldRenderer` receive the `MicButton` component inline. No visual changes to the field container; the mic button is absolutely positioned inside the input wrapper.

**Text field layout (single-line input):**
- Input wrapper: `relative` positioning.
- Input: `pr-12` right padding to prevent text overlapping the mic button.
- MicButton: `absolute right-2 top-1/2 -translate-y-1/2` — matches the existing `mic-button.tsx` positioning default.

**Textarea field layout:**
- Textarea wrapper: `relative` positioning.
- Textarea: `pr-12 pb-8` (extra bottom padding so the mic sits at bottom-right without overlapping text).
- MicButton: `absolute right-2 bottom-2` — pinned to bottom-right of textarea.

**Mic button states (carry-forward from existing `mic-button.tsx` — no new tokens):**
- Idle (supported): Mic icon, `h-8 w-8 rounded-full ghost`. Dark: `text-slate-400 hover:text-slate-200`. Cream: `text-[#6b6560] hover:text-[#1a1a1a]`.
- Recording: `bg-amber-500/20 text-amber-500 animate-pulse scale-110` + "Listening…" 9px mono uppercase label to left.
- Transcribing: `Loader2` spin icon, button disabled.
- Unsupported: `MicOff` icon, `opacity-60`. On click: Sonner toast "Speech-to-text isn't available in this browser. Try Chrome or Edge on desktop."

### attachPhotos Affordance

Rendered below every field renderer (between the field's error message and the next field in the form flow) when `attrs.attachPhotos === true`.

**attachPhotos affordance layout:**
```
[ Paperclip icon ] Attach photos   [ {N} attached ]   [ + Add Photo ]
```

- Container: `flex items-center gap-2 pt-2 mt-2 border-t border-dashed`. Border separates affordance from main field. Dark: `border-white/10`. Cream: `border-[#e5e1d8]`.
- Paperclip icon: `Paperclip` lucide icon, 14px, muted color.
- Label: "Attach photos" in 12px muted.
- Count badge (shown once ≥1 photo attached): "{N} attached" in 12px mono teal. Hidden when 0 photos.
- "+ Add Photo" button: ghost button, 12px, "Add Photo" label + Camera icon (12px). Opens file picker (`accept="image/*"`, `capture="environment"`). Dark: `text-white/40 hover:text-white/70`. Cream: `text-[#6b6560] hover:text-[#1a1a1a]`.

**Thumbnail strip (after upload):** Below the affordance row, a horizontal scroll strip shows uploaded photo thumbnails. Each thumbnail: `40px × 40px` (`w-10 h-10`), `rounded-sm`, `object-cover`, `border`. Remove button: `h-4 w-4` X icon, absolutely positioned top-right of thumbnail, appears on hover. `aria-label="Remove attached photo {N}"`.

**Upload states:**
- Adding: thumbnail cell shows `Loader2` spinner while `use-media-processor` runs.
- Failed: thumbnail cell shows a destructive `AlertCircle` icon + "Failed" 10px text overlay. Tap/click to retry.

**Positioning rule:** The affordance always renders as the last element inside the field renderer's container div, below the error message if one is showing. It is NOT a separate component rendered by the interpreter layout; each renderer that has `attrs.attachPhotos === true` renders `<AttachPhotosAffordance>` itself.

### Destructive Actions

| Action | Confirmation Approach |
|--------|----------------------|
| Remove repeating section instance | No confirmation dialog. Instance is removed immediately on X click. Rationale: fill-time state; user can re-add. Same philosophy as delete-field-from-canvas (no confirmation, Phase 13 pattern). |

## Accessibility Contract

Carry-forward Phase 13 rules plus Phase 14 additions:

- Signature canvas: `role="img"` with `aria-label="Signature pad — draw your signature"`. Clear button: `aria-label="Clear signature"`. Done button: `aria-label="Capture signature"`. Preview image: `alt="Captured signature"`.
- Rating field: each star button already has `aria-label="Rate {star} of {maxRating}"` (verified in `rating-field.tsx` line 52). The renderer wrapper must also add `role="group"` with `aria-label="{field label}"` on the star container.
- Map (`GeoMap`): wrap in `<div role="application" aria-label="Location map — click to adjust pin position">`. Map tiles are decorative; attribution link must remain accessible.
- Geolocation desktop badge: `role="alert"` so screen readers announce it on render.
- Repeating section:
  - Container: `role="group"` with `aria-label="{attrs.title}"`.
  - Each instance card: `role="group"` with `aria-label="Instance {N}"`.
  - Add button: `aria-label="Add {title || 'instance'}"`.
  - Remove button: `aria-label="Remove instance {N}"`.
  - Collapse button: `aria-label="Collapse instance {N}"` / `aria-expanded={isExpanded}`.
- Computed field: `role="status"` on the result badge so screen readers announce value updates. `aria-live="polite"`.
- attachPhotos affordance: file input must have `aria-label="Attach photo to {field label}"`. Thumbnail remove buttons: `aria-label="Remove attached photo {N}"`.
- STT mic button: existing `title` attribute covers hover tooltip. Add `aria-label` matching the `title` value explicitly for screen reader compatibility.
- Minimum touch targets: all interactive elements (star buttons, remove photo buttons, mic button, add-instance button, collapse buttons) must meet 40px minimum dimension (WCAG 2.5.5 target size 24px minimum; 44px recommended — use 40px as floor consistent with Phase 13 h-10 pattern where 48px is cost-prohibitive inline).
