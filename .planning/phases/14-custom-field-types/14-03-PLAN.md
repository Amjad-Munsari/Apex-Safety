## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client renderer → uploadMediaAction (server) | Untrusted file bytes + MIME header arrive as a base64 data URL; auth gate + MIME whitelist + size cap are the first filters |
| uploadMediaAction → adminClient.storage | Service-role write bypasses RLS — the path prefix `{clientId}/...` is purely advisory at this layer; correctness depends on the auth gate + the clientId arg coming from a server-fetched submission row (RSC), never user input |
| uploadMediaAction → field_media insert | Audit row; service-role write; submission_id + field_id values must come from trusted server-side context (RSC fetches submission, knows fieldId from the schema) |
| Pinned-schema fetch (runReportDraftGeneration) | submission.template_version_id is the only key — chosen at submit time (Phase 13 13-03 enforces this); cannot be tampered post-submit because form_submissions write is admin-gated |
| expandRepeatingSections output → AI prompt | Labelled flat objects are JSON.stringified into the GPT prompt; the AI sees user-supplied text. Prompt injection by users with admin access is the residual risk — accepted (admin trust boundary). |
