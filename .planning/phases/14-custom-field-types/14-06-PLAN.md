Phase 14 contract: deps stay `[surface]` (RESEARCH Pitfall 6 / Phase 13 13-04 UAT). NEW props that change per render (clientId, submissionId, interpreterStore, schema) are referenced inside the wrapper functions by lexical closure — they are read each time the wrapper fires (which is per-entity-render inside InterpreterEntities), not captured at useMemo time. Since the wrappers close over the parent component's props (which DO change), the closures will see fresh values without remounting the renderer.

Actually — re-read the existing code: the wrappers close over `surface` which is the only useMemo dep. Adding clientId / submissionId / interpreterStore / schema to the closures means they will become stale across renders if NOT added to the deps array. BUT adding them to deps re-introduces the focus-loss bug.

The correct fix: pass the props via the wrapper's lexical scope, BUT use `useRef` to give the wrappers a stable reference to the latest values. Pattern:
```typescript
const propsRef = useRef({ clientId, submissionId, schema, interpreterStore })
useEffect(() => { propsRef.current = { clientId, submissionId, schema, interpreterStore } })

const components = useMemo(() => ({
  signatureField: (props) => <SignatureFieldRenderer {...props} surface={surface} clientId={propsRef.current.clientId} submissionId={propsRef.current.submissionId} />,
  // ... etc
}), [surface])
```

This preserves the focus-loss fix (useMemo deps unchanged) while giving the wrappers always-fresh refs to props that may change. Document this pattern explicitly in the file with a JSDoc comment referencing RESEARCH Pitfall 6.
