The chosen fix is the migration path (option a in VERIFICATION.md) — the alternative (drop the column from the select + render a placeholder) would silently override D-04's "STT verbatim" intent, which the planner has no authority to do.
Output: A new idempotent migration file `017_phase07_field_media_transcript.sql` applied to the live Supabase project via the Supabase MCP, leaving the column nullable so existing `field_media` rows (which never had a transcript) remain valid.
