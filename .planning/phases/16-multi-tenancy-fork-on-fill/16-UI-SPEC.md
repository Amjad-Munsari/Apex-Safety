**Phase 16 introduces two surfaces.** Admin routes (`/admin/assignments`, `/admin/clients/[id]`) wear `data-surface="admin"`. Client routes (`/client/assignments`, `/client/templates`) wear `data-surface="client"`. The contracts below declare the per-surface values. The implementation must NEVER mix them (no `text-white` in a client-surface component; no cream backgrounds on admin routes).

## Spacing Scale

Declared values (multiples of 4 — consistent with existing admin and client route implementations):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact element spacing, button inner padding (`px-2 py-1`) |
| md | 16px | Default card inner padding, form field gaps (`gap-4`, `p-4`) |
| lg | 24px | Section padding, card grid gaps (`gap-6`) |
| xl | 32px | Layout-level vertical gaps between sections (`gap-8`) |
| 2xl | 48px | Major section breaks, top-of-page padding (`pt-12`) |
| 3xl | 64px | Page-level vertical padding on spacious admin layouts |

Exceptions:
- Assignment card padding: `p-5` (20px) — matches the existing `ClientTemplateCard` established pattern (`app/client/templates/_components/client-template-card.tsx:58`).
- Mono tag / badge internal padding: `px-2 py-1` (8px/4px) — exact match to existing status pill pattern in codebase.
- Touch target minimum for icon-only buttons: 28px × 28px (7rem Tailwind units — matches `h-7 w-7` pattern in `client-template-card.tsx`).

## Per-Route Visual Contracts

### Route A — `/admin/assignments` (queue page)

- **Layout:** Full-width server-rendered table. Same structure as `/admin/clients/page.tsx` (page header + `<Card>` wrapping `<Table>`).
- **Header pattern:** Back arrow link + mono route code + serif h2 + optional filter bar.
- **Filter bar:** Three `<Select>` dropdowns (Status, Client, Template) as `<Link>` to same URL with `?status=&client=&template=` searchParams. No client state.
- **Table columns:** Template | Client | Due Date | Status | Instructions (truncated) | Actions.
- **Status pill spec:**
  - `pending` — mono text-[9px] uppercase tracking-[0.25em], text-[#666], bg-[#555]/10 (grey)
  - `in_progress` — text-[#c0a66d] (gold-amber), bg-[#c0a66d]/10
  - `completed` — text-[#3b8273] (teal), bg-[#3b8273]/10
  - `revoked` — never shown (filtered by `deleted_at IS NULL`)
- **Due date colour coding:** If `due_date < today`: text-[#e55a3a] (destructive red). If `due_date` within 3 days: `text-gold`. Otherwise: text-[#666] muted.
- **Counter pill on `/admin/clients` list:** `font-mono text-[9px] uppercase tracking-[0.25em]` badge to the right of the client name. Shows count of active assignments (`status IN ('pending','in_progress') AND deleted_at IS NULL`). Colour: text-[#c0a66d] bg-[#c0a66d]/10 when count > 0; hidden (render nothing) when count is 0. **Do NOT show a zero — empty is the absence of the pill.**

### Route B — `/admin/clients/[id]` — Assigned Forms tab

- **Tab label:** "Assigned Forms" with the active-count appended in parentheses when > 0: "Assigned Forms (3)".
- **Tab content:** A flat list of assignment rows (not a full `<Table>` — matches the existing Documents tab pattern in the same page). Each row: Template name · Status pill · Due date · Revoke action.
- **"Assign template" button:** placed in the tab header, right-aligned. Text: "Assign template". Variant: outline (white-bordered ghost on admin surface). On click: opens `<AssignTemplateModal preselectClientId={id} />`.

### Route C — `/admin/templates/[id]` — Assign entry point

- **"Assign to clients" button:** Added to the existing page header toolbar. Text: "Assign to clients". Variant: outline. Icon: `<Share2 className="w-4 h-4" />` (lucide). On click: opens `<AssignTemplateModal templateId={id} />`.
- No layout changes; button slots next to the existing "Edit" / "Publish" buttons in the header.

### Route D — `/client/assignments` (Active + Completed tabs)

- **Surface:** `data-surface="client"`, cream background.
- **Page header pattern:** matches `/client/templates/page.tsx` exactly — mono route index + serif h2 + body subhead.
  - Mono index: `05 · Assigned Forms` (teal `#3b8273`)
  - Serif h2: `Forms assigned to you.` — 32px Newsreader, text-[#1a1a1a]
- **Tabs:** shadcn `<Tabs defaultValue="active">` with two `<TabsTrigger>` values `active` | `completed`. Default: Active.
- **Assignment card (Active tab):** White bg, `border border-[#e5e1d8]`, `rounded-sm`, `p-5`. Three rows:
  1. Template name — 18px Newsreader, text-[#1a1a1a]
  2. Mono metadata row: `DUE · {date}` · status pill (using same colour coding as admin)
  3. Instructions block (if `instructions IS NOT NULL`): 12px Inter, text-[#6b6560], italicised, max 2 lines clamped (`line-clamp-2`). Prefixed with `—` em dash.
- **Assignment card (Completed tab):** Same card structure. Adds a `View submission` text-link (`/client/assignments/[id]/submission`). Status pill shows "Completed" in teal.
- **Empty state — Active tab:**
  - Heading: "No forms assigned yet"
  - Body: "When Matt assigns a form to your organisation, it'll appear here."
  - No CTA button. Match existing empty-state pattern from Portal (centred, muted-foreground body).
- **Empty state — Completed tab:**
  - Heading: "No completed forms yet"
  - Body: "Submitted assignments will appear here for reference."

### Route E — `/client/assignments/[id]` (landing — Fill vs Customise)

- **Layout:** Single centred column, max-w-xl, `py-12 px-6`.
- **Top section:**
  - Mono back link: `← Back to Assigned Forms` — 12px JetBrains Mono, uppercase, text-[#8a857f].
  - Template name: 28px Newsreader, text-[#1a1a1a], `leading-[1.1]`.
  - Due date (if set): mono 10px, `DUE · {date}`. Colour: destructive red if overdue, muted otherwise.
  - Instructions block (if set): `bg-[#f5f3ee]` cream card, `rounded-sm`, `p-4`, 14px Inter, `text-[#1a1a1a]`, with a hairline left border `border-l-2 border-[#c0a66d]` (earth amber). Prefixed with a `<Info className="w-4 h-4 text-[#c0a66d]" />` icon and a "From your assessor" label in mono 9px.
- **CTA row:** Two buttons, side-by-side on desktop, stacked on mobile.
  - **"Fill as-is"** — primary black fill button, full-width on mobile. Text: "Fill as-is". Routes to `/client/assignments/[id]/fill`.
  - **"Customise first"** — outline button (black outline, transparent bg). Text: "Customise first". On click: triggers `<AlertDialog>` confirmation (see Copywriting below), not immediate navigation.
- **"Customise first" AlertDialog:**
  - Title: "Create your own copy?"
  - Body: "This creates your organisation's version of this form. Changes to the original won't carry over to your copy."
  - Cancel: "Keep original"
  - Confirm: "Create my copy" (black fill button)

### Route F — `/client/assignments/[id]/fill` (interpreter)

- **Visual:** Identical to existing `/admin/assessments/[id]` fill page. Same `InterpreterRenderer` component, same layout. Surface is `data-surface="client"` (cream).
- **Progress indicator:** Retain existing `<Progress>` bar pattern from admin assessments.
- **Submit button:** "Submit form" — black fill, full-width at bottom of form.
- **No design divergence** from the Phase 13 interpreter fill UX — this route is a surface swap only.

### Route G — `/client/templates` (simplified — My Templates only)

- **Remove:** The "Available Templates" / "01 — Available Templates" section and its mono divider. The `TODO(phaseB)` at line 17 is resolved.
- **Retain:** Page header, `<NewClientTemplateButton>`, and the "My Templates" section with `<ClientTemplateCard>` grid.
- **"My Templates" section label update:** Change from "02 — My Templates" to "My Templates" (no numbering, since there's only one section now).
- **"New template" button:** Already exists via `<NewClientTemplateButton>`. No visual change.
- **Forked template card indicator:** Retain the `· FORKED` suffix in earth amber (`text-[#c0a66d]`) on the mono metadata line — this is already implemented in `client-template-card.tsx`.

## Interaction States

### Assignment card — hover (client)

- `hover:border-[#1a1a1a]/30` on card border. Matches `client-template-card.tsx:58`.
- Cursor: `cursor-pointer` on the card link area.

### "Assign to clients" modal — multi-select

- Client checkbox list: scrollable `max-h-48 overflow-y-auto` area.
- Each row: `<Checkbox>` + client name label. Pre-checked row when `preselectClientId` prop provided.
- "Select all" affordance: not required in v1 (max ~8 clients at current scale).
- Due date input: native `<input type="date">` with `style={{ colorScheme: "dark" }}` on admin surface (matches `upload-document-modal.tsx:166-173` pattern exactly). Default: today + 7 days (ISO string).
- Instructions textarea: `<Textarea placeholder="Optional instructions for the client…" rows={3} />`.
- Empty template select warning: inline `text-[#e55a3a] text-xs` below the template `<Select>` if user clicks Assign without selecting. No full modal validation — just highlight the empty field.

### "Customise first" button — loading

- Button enters `disabled` + pending state via `useTransition`. Label changes to `Creating copy…` while the server action runs (typically <1s — fork is a 3-step DB write). No spinner icon — text change is the affordance.

### Status lifecycle — no optimistic update

- Status transitions (`pending → in_progress`, `in_progress → completed`) are server-side. The page RSC re-fetches on navigation. No client-side status mutation.

### Overdue due date

- Client assignments list: overdue due-date text becomes `text-[#e55a3a]` (destructive). No icon.
- Admin queue table: same colour. Add `<Tooltip>` showing "Overdue by {N} days" on hover.
